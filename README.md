# 数控车工刷题

一个离线 Android 刷题应用，面向**数控车工（中级）考证**理论考试。
实现了类似「在线100分」的**基础练习**与**模拟考试**，另含错题本、收藏、分类练习和答题统计。

题库 **1183 题**（单选 783 + 判断 400），全部内置在安装包里，**不联网、不申请任何权限**。

## 下载安装

到 [**Releases**](../../releases/latest) 页下载 `数控车工刷题-v1.0.apk`，传到手机点击安装，
按提示允许「安装未知来源应用」即可。支持 Android 5.0（API 21）及以上。

## 功能

**基础练习** — 按题库顺序或随机顺序逐题作答，答后立即显示对错、正确答案、你的答案和所属分类。
支持上一题 / 下一题、答题卡跳题、收藏标记。已作答的题目会记住结果，重复进入不会重置。

**模拟考试** — 两种出卷方式：

- **标准卷**（推荐）：严格按真实中级理论试卷结构出卷 ——
  **单项选择题 80 题 + 判断题 20 题，共 100 题，每题 1 分，满分 100 分**，建议时长 90 分钟。
  单选与判断按考试顺序分段排列，交卷后按 60 分及格线评分。
- **自定义卷**：自选题量（30 / 50 / 100）、时长（45 / 60 / 90 分钟）和范围（全部 / 仅选择 / 仅判断），
  适合日常练手。

两种方式都随机抽题并**打乱选项顺序**，考试过程中不显示任何答案。
倒计时归零自动交卷；交卷前提示未作答数量，交卷后显示对 / 错题数、用时、正确率，
并可一键回看本次错题。考试记录保留最近 30 次，并标注是标准卷还是自定义卷。

> **评分依据**：《车工国家职业技能标准（2018 年版）》规定，理论知识考试与技能操作考核
> 均实行百分制，**成绩皆达 60 分（含）以上为合格**——两科须各自合格，不存在加权合并。
> 理论考试时间不少于 90 分钟。详见 [考试规则说明](docs/考试规则.md)。

**错题本 / 收藏 / 统计** — 答错的题自动进错题本；统计页显示整体进度、各分类掌握度与历次考试成绩。

所有记录存在本机（WebView localStorage），卸载应用即清除，不会上传到任何地方。

## 题库

题目从《数控车工中级考证理论题》Word 文档解析而来，**答案一律照抄原文**
（题干中的 `(A)` 括号，或独立的 `答案:X` 行），未做任何主观改答。
已逐条回查原始文档校验：题干、全部选项、答案字母**零偏差**。

### 分类

按题干关键词自动归为 10 类（`tools/build_bank.py` 中的 `RULES`），便于分块攻克：

| 分类 | 题量 | 分类 | 题量 |
|---|---:|---|---:|
| 车削工艺与刀具 | 335 | 机床结构与维护 | 54 |
| 数控编程与操作 | 210 | 钳工与电工基础 | 41 |
| 测量与检验 | 148 | 职业道德与素养 | 37 |
| 机械制图与公差 | 133 | 安全文明生产 | 29 |
| 综合 | 115 | 金属材料与热处理 | 81 |

### 关于源文档中的残缺条目

原始文档共 1599 个「题干」，但并非 1599 道题：

- **800 道**带 ABCD 选项的选择题 + **400 道**判断题 = 1200 道正题；
- **399 条**是「只有题干 + 答案文字、没有选项」的条目。经归一化精确比对，它们的题干与前面
  800 道选择题**逐字完全相同**（399/399 命中），属于同一份题库的残缺副本，不是新题，
  因此未重复计入；且其答案与正题有 320 条互相矛盾，参考价值低。

此外：

- 合并了 **12 条完全重复**的题目（同一题干出现两次）。其中 8 条两处答案不一致，按**首次出现**保留；
- 剔除 **4 道**源文档本身残缺、无法作答的题目：2 道没有答案（「哪种防护用品是必需的」、
  「控制切削速度的主要目的」），2 道选项被破坏（「气源压力单位」的选项为 der/ber/ke、
  「读数单位」里 mc/me 无意义）。这几道全文只出现一次，补不出来。

最终 **1183 题** = 783 单选 + 400 判断。

## 自行构建

### 环境

```
JDK 11 · Gradle 7.5（用仓库自带 wrapper）· Android SDK（compileSdk 32 / build-tools 33.0.2）
```

### 构建 APK

```bash
cd android
# 指向你自己的 Android SDK
echo "sdk.dir=/path/to/android-sdk" > local.properties
./gradlew assembleRelease
# 产物：android/app/build/outputs/apk/release/app-release.apk
```

仓库里的 `quiz.keystore` 是**自签名测试证书**，口令就写在 `app/build.gradle` 里（不是机密）。
保留它是为了让 Release 包能覆盖安装（签名一致）。删掉这个文件也能构建，只是不再签名。

### 从 Word 文档重新生成题库

需要先把 `.doc` 转成 `.docx`（Word / WPS 打开后另存为即可），然后：

```bash
# 需要 python-docx
pip install python-docx

python tools/build_bank.py source/qbank.docx data/qbank.json   # 解析文档
python tools/make_assets.py                                     # 同步到 assets/www/qbank.js
```

`source/` 目录不入库（题目内容版权归原出版方，见下）。

```
├── app/src/main/

│   └── assets/www/                               # 刷题应用本体
│       ├── index.html   # 页面骨架
│       ├── style.css    # 样式
│       ├── app.js       # 全部逻辑
│       └── qbank.js     # 题库（内联为 JS 变量）
└── build.gradle / settings.gradle

tools/make_assets.py             JSON → qbank.js 同步脚本
docs/screenshots/                README 截图
```

### 几个实现要点

- 页面通过 `WebViewAssetLoader` 以 `https://appassets.androidplatform.net/` 提供，而**不是** `file://`——
  否则 localStorage 不可用，练习记录就存不下来。同源策略下也不需要任何网络权限。
- 题库以 `window.QBANK=...` 内联进 `qbank.js`，而非运行时 `fetch`，避开 `file://` 的 CORS 限制。
- 返回键先交给页面处理（关答题卡、关弹窗、回上一屏），页面不处理才退出应用。
- 答题记录存的是**所选选项的原始下标**（不是 0/1 对错标记），避免与答案下标语义冲突。
- 考试页因打乱选项，另存「显示下标 → 题库原始下标」的映射，交卷时换算回写，保证错题本正确。
